# Backend, security and production integration

## Which defects affect availability, bookings and staff workflows?

### Takeaway

The highest-impact availability defect is a live hero edit that can break catalog reads and booking submissions together. Ordinary use of the mixed-tour builder and seasonal price editor also exposes inconsistencies.

### Cited Findings

- **High. A live hero can invalidate the entire catalog.** A manager’s patch accepts null for the headline and collection, and only rechecks media when the slide is already published. A slide with a valid cover and neither text source produces a null title where the public schema requires text. The shared loader parses the whole site for trip, collection, FAQ and booking calls, so this can produce 500s across several customer paths after caches expire. Publishing initially checks a headline, but live edits bypass that rule. Reuse a single validator for merged live slide data, including published collection references, validated CTA targets and schedule, and isolate an unusable slide from unrelated reads. Add a manager-edit regression. [Patch](F:/stella-project-kit/apps/api/src/admin.ts:1408) [Permitted values](F:/stella-project-kit/packages/shared/src/admin.ts:166) [Public parser](F:/stella-project-kit/apps/api/src/catalog.ts:444) [Required title](F:/stella-project-kit/packages/shared/src/public-contract.ts:115) [Booking dependency](F:/stella-project-kit/apps/api/src/requests.ts:51)
- **High. A mixed group/private itinerary defaults to a rejected format.** My Trip opens with group mode. The store switches to private only when every item is private. The client calculates a per-trip private price for a private-only item but submits a single group format. The API rejects it. A customer with one private-only tour and one ordinary tour can see an estimate, complete the form and get a generic failure. For mixed itineraries make permitted per-item formats explicit, or derive one permitted mode across all items and show it before the form. [Builder](F:/stella-project-kit/apps/web/src/components/my-trip.tsx:196) [Request store](F:/stella-project-kit/apps/web/src/components/store.ts:106) [Estimator](F:/stella-project-kit/packages/shared/src/price.ts:86) [API rejection](F:/stella-project-kit/apps/api/src/requests.ts:81)
- **High for seasonal prices. Later excursions use the first date’s rates.** The API filters every trip’s price rows using the overall start date before it computes each trip’s scheduled day. A second excursion after a seasonal change can therefore be underquoted or overquoted and the wrong amount is saved in its snapshot. Browser prices are built using the current Cairo date, so even a single future trip can show today’s price or send an option ID that is unavailable for travel. Calculate the itinerary first, resolve each option for its service date, and show a date-aware quote before submission. Test both sides of a rate boundary and a withdrawn option. [Date filtering](F:/stella-project-kit/apps/api/src/catalog.ts:241) [Default date](F:/stella-project-kit/apps/api/src/catalog.ts:91) [Booking calculation](F:/stella-project-kit/apps/api/src/requests.ts:52) [Plan](F:/stella-project-kit/apps/api/src/requests.ts:99)
- **Medium. A retry can create a second booking and notification.** The client retries a generic failure using an ordinary POST. Every accepted POST generates a new reference and inserts another booking and notification, with no operation key. A response lost after commit is sufficient. Generate a per-submission ID in the form, enforce uniqueness in the same transaction, and return the stored confirmation when the same ID and payload recur. [Client submission](F:/stella-project-kit/apps/web/src/components/request-sheet.tsx:161) [Reference](F:/stella-project-kit/apps/api/src/requests.ts:129) [Insert](F:/stella-project-kit/apps/api/src/requests.ts:179) [Schema](F:/stella-project-kit/packages/db/src/schema.ts:438)
- **Medium. Archived or failed uploads cannot be recovered by uploading the same file.** Deduplication returns the existing row regardless of archive or processing status and deletes the newly uploaded file. The library excludes archived rows and the worker skips them. After 30 days cleanup can remove the only original while the digest still blocks a replacement. Restore the original and requeue on explicit reactivation or retry, while retaining the ordinary ready-asset reuse behavior. [Upload](F:/stella-project-kit/apps/api/src/media.ts:292) [Worker](F:/stella-project-kit/apps/api/src/media.ts:340) [Library](F:/stella-project-kit/apps/api/src/admin.ts:1574) [Cleanup](F:/stella-project-kit/apps/api/src/jobs.ts:372)
- **Medium. The admin trip-date filter can return a booking with zero activities in the selected range.** Its two independent EXISTS checks may match different items, one later than the range and another earlier. This affects inbox counts as well as the list. Put both comparisons inside one item predicate. A request with outings on the 1st and 10th should be excluded for a 4th–6th filter. [Filters](F:/stella-project-kit/apps/api/src/admin.ts:573) [Counts](F:/stella-project-kit/apps/api/src/admin.ts:594) [List](F:/stella-project-kit/apps/api/src/admin.ts:625)
- **Medium. CSV export has misleading scope.** The button calls a fixed URL regardless of the visible inbox filters. The API selects the latest 10,000 requests globally, including records outside the current view, and silently drops older records. Show the export scope and count in advance, apply the selected filters by default and provide a paginated or streamed full export when requested. [Dashboard button](F:/stella-project-kit/apps/admin/src/screens/requests.tsx:91) [API export](F:/stella-project-kit/apps/api/src/admin.ts:389)
- **Medium at scale. A permitted bulk-price preview can be impossible to apply.** Preview accepts up to 5,000 rows, embeds both UUIDs and both amounts for each in a signed base64 token, then apply limits the token to 120,000 characters. Many valid previews exceed that limit (even 1,000 ordinary rows are enough). Store a short-lived preview server-side or enforce a tested common limit before emitting a preview. [Preview](F:/stella-project-kit/apps/api/src/admin-more.ts:1067) [Token encoding](F:/stella-project-kit/apps/api/src/admin-more.ts:1115) [Apply](F:/stella-project-kit/apps/api/src/admin-more.ts:1130)
- **Low. The FAQ translation cache tag has a different spelling in the writer and the reader.** Translation review emits plural `faqs`; the worker only allows singular `faq`, and the web FAQ fetch uses singular. An approved FAQ translation can remain cached until normal expiry. Use shared tag constructors and an end-to-end cache assertion. [Writer](F:/stella-project-kit/apps/api/src/translation-review.ts:36) [Worker](F:/stella-project-kit/apps/api/src/jobs.ts:295) [Reader](F:/stella-project-kit/apps/web/src/lib/api.ts:69)
- **Medium. Several operational and customer messages still contain English.** In a dated WhatsApp request the stay’s day/night units are hard-coded in English even when the request title and guest labels are localized. Weekly price email, request email, setup/reset subjects and the schedule-review notice also contain fixed English. Use a shared seven-language template with pluralization and use a staff delivery locale for staff communications. [Customer message](F:/stella-project-kit/apps/api/src/requests.ts:132) [Review note](F:/stella-project-kit/apps/api/src/requests.ts:201) [Weekly price email](F:/stella-project-kit/apps/api/src/jobs.ts:213) [Request email](F:/stella-project-kit/apps/api/src/jobs.ts:250) [Authentication emails](F:/stella-project-kit/apps/api/src/jobs.ts:456)

## Which security boundaries and operational controls need attention?

### Takeaway

Revoking a media asset’s usage rights does not remove the earlier copy already exposed by the media host. Runtime privileges and deployment coordination also have avoidable failure modes.

### Cited Findings

- **High. Revoking media rights can leave the original public URL serving indefinitely.** After staff detach an asset and set its rights to unknown, processing writes future variants into private previews. Public variants have the same relative key, since rights are excluded from the variant hash. Cleanup tracks only the relative key across both roots. The live private preview therefore keeps the old public directory referenced. Caddy still serves those bytes at the previously known URL, with a one-year immutable caching policy. Remove or deny the public copy as part of revocation, distinguish roots when garbage collecting, and document the limits of revoking client-cached copies. Verify origin access stops for a formerly published asset. [Rights update](F:/stella-project-kit/apps/api/src/admin.ts:1697) [Variant hash and roots](F:/stella-project-kit/apps/api/src/media.ts:356) [Shared reference set](F:/stella-project-kit/apps/api/src/jobs.ts:331) [Public serving](F:/stella-project-kit/infra/caddy/common.caddy:16)
- **Medium security hardening. The worker has broad access to admin identities and the audit trail.** The migration grants both runtime roles SELECT, INSERT, UPDATE and DELETE on every table in the public schema, including staff roles, sessions and audit history. The default grants extend this to future tables. A worker failure or compromise has a much larger impact than media, translation or notifications require. Use explicit per-table/column grants, isolate security-sensitive keys, and test privileges under each runtime identity. This is a configuration finding, with no incident evidence. [Migration](F:/stella-project-kit/scripts/migrate.ts:11) [Default grants](F:/stella-project-kit/infra/postgres-init-prod.sh:12) [PostgreSQL privilege model](https://www.postgresql.org/docs/16/sql-grant.html)
- **High conditional deployment race. Staging and production can use one another’s checkout.** The workflow allows one concurrent release per environment, but both SSH commands change the same VPS working directory to their own SHA. The file locks are environment-specific and acquired after checkout. Concurrent releases can therefore copy or run deployment scripts, proxy configuration, and compose files from a different commit than the image SHA. Use immutable per-release/per-environment checkouts or hold a host-wide lock over checkout and the whole script. Verify overlapping staging and production releases in isolation. [CI concurrency](F:/stella-project-kit/.github/workflows/release.yml:9) [Shared server checkout](F:/stella-project-kit/.github/workflows/release.yml:78) [Environment lock](F:/stella-project-kit/infra/lib.sh:43) [Config snapshot](F:/stella-project-kit/infra/deploy.sh:18)
- **Medium. The default incident alert reaches only the local journal.** An unhealthy service or overdue backup can fail the scheduled check while the supplied alert service simply invokes logger on the same machine. Real external alert delivery, backup recovery, production SMTP, legal publication and VPS acceptance are expressly open in project documentation. Connect and test an external notification and independent uptime check; record an isolated, timed off-site restore before go-live. [Unit](F:/stella-project-kit/infra/monitoring/stella-alert@.service:5) [Checks](F:/stella-project-kit/infra/monitoring/check.sh:13) [Deployment gates](F:/stella-project-kit/infra/server-setup.md:84) [Security gates](F:/stella-project-kit/docs/04-security-plan.md:13)
- **Medium. CI does not run the dedicated admin, seven-language or integrated browser suites.** CI runs unit and database integration tests and the default public-site browser suite against its fixture; the named admin, API, real integration and language Playwright commands exist separately. A fresh green release check alone cannot substantiate the attached browser-coverage claim. Add representative release gates with isolated test data, then run broader locale matrices on a scheduled job if duration requires it. [CI workflow](F:/stella-project-kit/.github/workflows/ci.yml:50) [Named suites](F:/stella-project-kit/package.json)

### Inferences

- Rights revocation and release coordination are verified source defects. Exposure or concurrent deployment on the client’s VPS has not been observed. [Origin serving](F:/stella-project-kit/infra/caddy/common.caddy:16) [Deploy command](F:/stella-project-kit/.github/workflows/release.yml:78)

### Gaps

- No production-host checks, credential tests, codec probing, attack traffic, customer-data export, restore, or incident investigation were performed.

## Where is performance work likely to help?

### Takeaway

The code performs catalog-wide reads when one item is needed and catalog-wide invalidation after narrow edits. These are measurable targets even with the current small catalog.

### Cited Findings

- **Medium. Small reads and bookings materialize the whole catalog.** The loader runs eleven top-level reads, including complete price, item, itinerary and relation tables, and linearly scans translations repeatedly per text field. Site, single-trip, FAQ and message handlers all invoke it. Booking runs those reads sequentially inside a repeatable-read transaction. Narrow queries to requested published IDs and dates, index translations once per load, and measure cold-cache p95, query count and pool wait. [Loader](F:/stella-project-kit/apps/api/src/catalog.ts:94) [Per-field scan](F:/stella-project-kit/apps/api/src/catalog.ts:185) [Public handlers](F:/stella-project-kit/apps/api/src/app.ts:232) [Sequential booking](F:/stella-project-kit/apps/api/src/requests.ts:52)
- **Medium. Updating one trip can evict every trip and collection.** A trip/collection tag expands to the full list of slugs, then sends invalidations in batches. Bulk edits enqueue a change per trip. This multiplies both invalidation traffic and cold reads. Coalesce one logical mutation and tag only affected trip, collection, home, package and locale dependencies. [Expansion](F:/stella-project-kit/apps/api/src/jobs.ts:278) [Bulk loop](F:/stella-project-kit/apps/api/src/admin-more.ts:1179)
- **Medium. All server-rendered customer misses share an API rate bucket per web server.** Internal Next fetches use one source IP, and only configured proxies can supply the client IP. The same per-IP budget defaults to 600 reads/minute, so many legitimate distinct visitors during a cold-cache period can jointly throttle the storefront. Retain per-client controls at the public edge, apply a separate authenticated internal read budget and test a representative cold-cache burst. [Next fetch](F:/stella-project-kit/apps/web/src/lib/api.ts:26) [IP resolution](F:/stella-project-kit/apps/api/src/auth.ts:87) [Limiter](F:/stella-project-kit/apps/api/src/app.ts:115) [Default](F:/stella-project-kit/apps/api/src/config.ts:36)
- **Medium. One authenticated admin read can write the same session three times.** The contract middleware runs the guard, the blanket admin middleware runs it again, then many routes apply their own guard. Each invocation reads the staff/session row and writes last-seen. Reuse the validated principal within each request, keep permission checks at every required boundary, and throttle activity timestamp updates to a short interval. [Contract guard](F:/stella-project-kit/apps/api/src/app.ts:367) [Blanket/route guards](F:/stella-project-kit/apps/api/src/admin.ts:358) [Per-guard write](F:/stella-project-kit/apps/api/src/auth.ts:228)
- **Medium. Push delivery retries can duplicate notifications and delay other staff.** Delivery loops over all recipients in a single job. One transient failure throws, causing the next job attempt to begin with the first recipient; later recipients may never be reached during repeated failures. Track per-subscription delivery or enqueue independently with bounded concurrency and retry accounting. [Loop](F:/stella-project-kit/apps/api/src/push.ts:155) [Job retries](F:/stella-project-kit/apps/api/src/jobs.ts:42)
- **Low. Production runtime images copy the whole installed monorepo.** Each final stage includes the full build/source tree and development dependencies, increasing registry size, deployment traffic and software inventory. Use traced Next standalone output for web/admin and a pruned production dependency tree for API/worker, keeping the migration/seed path available as a separate operations target. Measure resulting image size and cold deploy duration. [Dockerfile](F:/stella-project-kit/infra/Dockerfile:36)

### Inferences

- The amount of avoidable work is visible in source, but no production latency, throughput or savings figure was measured. [Catalog reads](F:/stella-project-kit/apps/api/src/catalog.ts:94)

### Gaps

- Production pool saturation, Core Web Vitals, cache-hit rates, backup restore time, mail delivery and VPS exposure need separate environment evidence.
