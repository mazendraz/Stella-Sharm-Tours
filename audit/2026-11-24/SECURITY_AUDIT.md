### SEC-02 · Production release does not enforce a recorded staging acceptance

|            |                                                                                                                                                                                                                                                                                                                                                                 |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Severity   | **Low / process**                                                                                                                                                                                                                                                                                                                                               |
| Confidence | High — CONFIRMED by reading `.github/workflows/release.yml`                                                                                                                                                                                                                                                                                                     |
| Detail     | A `v*.*.*` tag deploys to production when CI passes and the SHA is an ancestor of both `main` and `develop`. `scripts/verify-staging-gate.mjs` exists but is not invoked by any workflow; staging acceptance is a manual convention. The production GitHub Environment may have required reviewers configured — that could not be verified from the repository. |
| Fix        | Either require reviewers on the `production` environment (GitHub settings) or have the deploy job check a staging-acceptance record for the exact SHA.                                                                                                                                                                                                          |

### SEC-03 · Anyone who knows a staff e-mail can lock that account out

|          |                                                                                                                                                                                                                                                                                                                            |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Severity | **Info** (deliberate trade-off)                                                                                                                                                                                                                                                                                            |
| Code     | `apps/api/src/auth.ts:416-448`                                                                                                                                                                                                                                                                                             |
| Detail   | Login is limited to 5 attempts per account per 15 min and failed logins add an exponential `locked_until` (up to 1 h). This blocks guessing but lets an outsider keep a known staff account locked. Owner/manager accounts also need TOTP, so the credential-stuffing benefit of the lockout is smaller than its DoS cost. |
| Option   | Keep the per-account bucket but drop the persistent lockout for accounts with TOTP enabled, or let a valid password + valid TOTP bypass the lock. Decide explicitly; no change is required.                                                                                                                                |

### SEC-04 · In-memory rate limits are per-process and evict under pressure

|          |                                                                                                                                                                                                                                                                                                                                                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Severity | **Info** (documented trade-off, `packages/shared/src/window-limiter.ts`)                                                                                                                                                                                                                                                                                                                                                 |
| Detail   | Public read limits (API) and `/api/*` proxy limits (web) are kept in process memory: they reset on restart and, above 10,000 keys, the oldest buckets are evicted. A caller controlling many IPv6 /64s can therefore exceed the per-address limit. Booking/quote/login limits use the PostgreSQL `rate_buckets` table and are not affected. Each new key while the map is full and unexpired also triggers an O(n) scan. |
| Option   | Accept for a single-VPS deployment; add a Caddy-level rate limit if abuse is observed.                                                                                                                                                                                                                                                                                                                                   |

### SEC-05 · Release deploy job leaves the checkout token on disk

|          |                                                                                                                                                                                                          |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Severity | **Info**                                                                                                                                                                                                 |
| Code     | `.github/workflows/release.yml` deploy job `actions/checkout` (no `persist-credentials: false`)                                                                                                          |
| Detail   | The token is `contents: read` only and the job runs no third-party code after checkout, so impact is minimal. CI (`ci.yml`) already sets `persist-credentials: false`; do the same here for consistency. |

### SEC-06 · FFmpeg/ffprobe parse uploaded files inside the API container

|          |                                                                                                                                                                                                                                                                                                                                    |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Severity | **Info**                                                                                                                                                                                                                                                                                                                           |
| Code     | `apps/api/src/media.ts:46-92, 93-239`                                                                                                                                                                                                                                                                                              |
| Detail   | Only authenticated staff with the media permission can upload, files are type-checked by magic bytes first, ffprobe runs with `-protocol_whitelist file,pipe`, a 15 s timeout, a 1 MB output cap and a scrubbed environment, and the container is read-only with all capabilities dropped. Residual risk is a codec CVE in FFmpeg. |
| Option   | Keep the Debian `ffmpeg` package current (rebuild images on security updates); optionally move probing to the worker container.                                                                                                                                                                                                    |
